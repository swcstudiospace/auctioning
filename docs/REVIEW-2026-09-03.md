# Codebase review — 2026-09-03

Scope: every crate, the migrations, the marketing site, and the seeder, read
end to end. Everything below was checked against a fresh
`cargo build --workspace` + `cargo test --workspace` (all green, 96 unit +
10 integration + program/magicblock tests) and `cargo clippy --all-targets`
on rustc 1.98.1.

Verdict in one line: **the business logic is well designed and well tested;
the HTTP edge is not yet safe to expose to the public internet.** The gap is
authentication and abuse control, not engine quality.

---

## 1. What the product is (as the code encodes it)

auctioning.lol is *Pay-to-Rank as a motorsport*. Businesses ("projects") are
cars. Supporters buy paid RP ($1 = 1 RP, Whop) or earn promotional RP (weekly
stipend, content reads, event cards) and allocate it to a car. Rank on every
board is a fold over the append-only `project_allocations` table:

| Concept | Where | Notes |
|---|---|---|
| Lifetime board | `race_engine::lifetime_grid` | open-ended window from epoch |
| Windowed race (Grand Tour weekly, Green Flag Saturday sprint) | `race_windows` + `compute_grid` | velocity = last 3600 s, momentum = Δ vs prior hour, burst = last 900 s |
| Overtake / lead change / photo finish / dark horse | `compute_grid` vs previous `rank_snapshots` | events feed the narrative tape |
| P1 paid floor | `compute_grid` | a zero-paid leader is swapped with the best paid slot — **this is the Pay-to-Rank guarantee** |
| Championship points | `championship.rs` | F1-style 25/18/15… for GP, 8/7/6 for sprints, +1 fastest pace |
| Featured race | `featured.rs` | `25·O + 20·P + 15·U + 10·M + 10·T + 10·D + 10·A`, all clamped 0..100 |
| Event cards | `events.rs` | Afterburner 1.5× adds `event_multiplier` *lots*; `paid_rp` never inflates |
| Live ER ticks | `ticks.rs`, `magicblock/` | `(session_id, seq)` identity; tick rows never rewrite allocation-derived events |
| Public receipts | `programs/auctioning` | `log_paid_rp` writes an immutable `RpReceipt` PDA; free RP never enters |

The invariants are stated in code comments, enforced by CHECK constraints,
and covered by unit tests. That is rare and worth protecting (hence the
"RP / money impact" section in the new PR template).

## 2. Blocking before public launch (P0)

### 2.1 No caller authentication on money-moving endpoints

`POST /v1/rp/spend`, `POST /v1/rp/claim-weekly`, `POST /v1/content/read`,
`POST /v1/projects/{handle}/support`, `POST /v1/races/open`,
`POST /v1/races/{pda}/{id}/settle` all take `wallet` **as a JSON field**.
Anyone can spend, allocate, or claim on behalf of any base58 string.
`ledger::valid_wallet` only checks the format.

Fix (the client half already exists — `public/phantom.js` exposes
`signMessageUtf8`):

1. Add **Sign-In-With-Solana** (SIWS / `signMessage` of a server nonce).
   `GET /v1/auth/nonce?wallet=` → `POST /v1/auth/verify {wallet, signature}`
   → short-lived JWT (or opaque session row) bound to the wallet.
2. Introduce an axum extractor `AuthedWallet` and replace every `req.wallet`
   with it. Reject a mismatch between body wallet and token wallet.
3. `ed25519-dalek` (or `solana_sdk::signature::Signature::verify`) is already
   transitively in the tree.

### 2.2 Operator endpoints are public

`POST /v1/races/windows/{slug}/snapshot`, `.../events/{id}/narrate`,
`POST /v1/narrative/posts/{id}/approve|skip|mark-published`,
`GET /v1/narrative/queue`, `GET /v1/oauth/supergrok/status` have **no gate**
(only `login` checks the ingest secret). Anyone can approve social copy or
force snapshots (which also create narrative events → drafts → LLM calls).

Fix: a dedicated `OPERATOR_TOKEN` secret and a single `require_operator`
extractor. Do not reuse `INGEST_SECRET` (that is for machine-to-machine
seeding and ticks).

### 2.3 `INGEST_SECRET` is optional

`check_ingest` returns `Ok(())` when the secret is unset ("dev mode"). A
mis-deployed prod without the secret opens `/v1/rp/earn` (mints free RP) and
`/v1/projects/import`. Make it **required unless `APP_ENV=dev`**, and fail
boot otherwise. Same for `WHOP_WEBHOOK_SECRET`.

### 2.4 CORS is `permissive()` and there is no rate limiting

* Lock CORS to `https://auctioning.lol`, the Vercel preview pattern, and the
  Leptos origin (`tower_http::cors::AllowOrigin::predicate`).
* Add `tower_governor` (or a Postgres-backed token bucket) on:
  `submit_project` (public, unauthenticated → catalog spam),
  `record_project_click` (public → clicks inflate CPC and the
  `attention` featured signal), `claim_weekly`, `support_project`.
* Add `RequestBodyLimitLayer` (axum default is 2 MB; import allows 5 000
  projects — fine, but cap explicitly) and `TimeoutLayer`.

### 2.5 Whop webhook amount units are ambiguous

`whop::parse_paid_event` treats flat `data.amount` as **dollars** and
multiplies by 100; the comment two lines up says Whop sends `1990` for
`$19.90` (i.e. cents). The unit test locks in the dollars interpretation
(`1990 → 199000 cents → 1990 RP`). If Whop actually sends cents this credits
**100× too much paid RP**. Confirm against a real webhook payload before any
money flows, and store the raw payload in a `whop_webhook_log` table so it can
be replayed.

### 2.6 `verify_webhook_signature` is not constant-time

The comment says constant-time; the code does `eq_ignore_ascii_case`. Use the
`constant_time_eq` helper that already exists three times in the crate (see
§4.1) or `subtle::ConstantTimeEq`.

### 2.7 The program keypair location

`keys/auctioning-keypair.json` exists on this machine at the repo root. It is
gitignored (verified: not tracked) but it is the **program upgrade identity**.
Move it into a password manager / KMS now and keep only `keys/.gitkeep`.
Consider `solana program set-upgrade-authority` to a Squads multisig at deploy.

## 3. Should fix before launch (P1)

### 3.1 Anchor program

The user note "we don't have our Anchor application yet" is accurate in the
sense that **nothing is deployed** (`Anchor.toml` cluster = localnet,
`ON_CHAIN_ENABLED=false`). The source is complete and PDA-pinned. Before
deploying:

* `Project` PDA is `["project", owner]` → **one project per wallet**. A
  business with two brands, or an agency, cannot register twice. Consider
  `["project", owner, handle_hash]` or a per-owner nonce. Changing seeds later
  is a migration; changing them now is free.
* `log_paid_rp` restricts `payer` to `project.owner` or the protocol
  authority. That means *supporters cannot write their own receipt* — only the
  business can. If the product story is "fans fuel cars", the receipt should
  allow any payer (and the backend already credits any wallet from Whop).
  Decide which story is true and align program + backend.
* `RaceResult` is `Copy` with a `Vec` in `Race` sized for 16 → fine, but
  `settle_race` accepts an **empty** results vec and `results.len() <= 16`
  without checking `rank` uniqueness or ordering. Add
  `require!(results.windows(2).all(|w| w[0].rank < w[1].rank))`.
* No `update_config` / `set_fee` / `pause` instruction. Once `initialize` runs
  the fee is frozen unless you redeploy. Add an authority-gated
  `update_config(fee_bps, fee_vault)` and a `paused: bool`.
* `Anchor.toml` at the root and `programs/auctioning/Anchor.toml` disagree
  (`resolution=true` vs `seeds=false`, localnet vs devnet, cargo test vs
  ts-mocha). Keep one — the root one — and delete the nested copy.
* There are no **on-chain integration tests** (only pure PDA/layout tests).
  Add a `solana-program-test` / `litesvm` suite for the five instructions,
  including the "wrong fee_vault" and "settle twice" failure paths. This is
  the single biggest test gap in the repo.
* `idl/auctioning.json` is hand-maintained — regenerate with `anchor build`
  in CI once anchor-cli is pinned (`anchor-lang 1.1` ⇒ anchor-cli 1.1.x).

### 3.2 Backend architecture

* **Duplicate helpers**: `check_ingest` + `constant_time_eq` are copy-pasted in
  `handlers.rs`, `ticks.rs`, `oauth_llm.rs`. Move to `src/auth.rs` as an
  extractor.
* **`tests/inc/` hack is obsolete**: `ledger` and `catalog` are `pub mod`
  now, so `tests/integration_rp.rs` can `use shuttle_auctioning::ledger`.
  Delete `tests/inc/`, `scripts/gen-integration-includes.sh`, and the 18
  dead-code warnings go with them.
* **N+1 in `featured_race_from_windows`**: per live window it runs
  `grid_for_window` (which itself calls `lifetime_grid` → full table scan of
  `project_allocations`) plus two more queries. With 50 windows that is
  ~150 queries per `GET /v1/races/calendar`. Cache `lifetime_grid` (it only
  changes on allocation) and pass it in.
* **`lifetime_grid` loads every allocation ever** into memory on every grid
  request. Add a materialised `project_totals` (already half-exists as
  `projects.total_rp`) or a `SUM … GROUP BY` query, and keep `compute_grid`
  for windows only.
* **Race worker is a stub**: it builds delegate instructions and logs
  "overdue" but never settles. Either implement the settle path
  (`auctioning_core::send_settlement` exists) behind `ON_CHAIN_ENABLED`, or
  document it as intentionally manual.
* **Boot ordering**: `build_app` runs migrations, seeds, sweeps, and spawns
  the worker *before* the router exists; a slow sweep delays `/healthz`.
  Split into `migrate()` → serve → background sweeps, and make `/healthz`
  report DB connectivity (`SELECT 1`) and migration version.
* **Idempotency on `credit_paid_with_card`**: the tx_id existence check and
  the insert are two statements outside one transaction; two concurrent Whop
  retries can double-credit the *bonus* lot (paid is protected by the unique
  index). Wrap in a transaction with `SELECT … FOR UPDATE` on the wallet row.
* **Config default drift**: `WEEKLY_FREE_RP` is 50 in `config.rs` and
  `.env.example`, 100 in `docs/RUNBOOK.md` (now fixed in
  `Secrets.toml.example`). Pick one.
* **Observability**: `TraceLayer` is on, but there is no request-id, no
  metrics endpoint, and no structured JSON logs. Add `tower_http::request_id`,
  `axum-prometheus` (or `metrics-exporter-prometheus`) at `/metrics` gated by
  the operator token, and `tracing_subscriber::fmt().json()` when
  `APP_ENV=prod`.
* **OpenAPI**: 45 routes and zero machine-readable spec. `utoipa` +
  `utoipa-swagger-ui` with the existing serde structs gives the marketing
  team and the Leptos app one source of truth (`marketing/lib/api.ts` is
  currently a hand-typed mirror with optional fields everywhere).

### 3.3 Data / BI

* `rank_snapshots` grows by `n_projects` rows per snapshot per window with no
  retention. Add a partition or a monthly `DELETE … WHERE snapshot_at < now()
  - interval '90 days'` job, keeping the *final* snapshot per window (the
  championship depends on it).
* `project_allocations` needs an index on `(created_at)` for the un-tagged
  window query, and `(source, created_at)` for the unique-payers query.
* `race_events.payload` stores `rp_delta`; the narrative "why clauses" cite
  it. Good. But `rank_snapshots` doesn't store `paid_rp` / `community_rp`
  split, so historical "how they did it" cannot say *paid vs community*.
  Add both columns (additive migration 0009).
* No analytics views. Two SQL views would unlock dashboards immediately:
  `v_window_finals` (last snapshot per window, joined to `race_windows`) and
  `v_wallet_daily` (RP in/out per wallet per day by source). Point Metabase /
  Supabase at read replicas.
* Whop `product` / plan id is parsed and then dropped (`field product is
  never read`). Persist it — tier-based pricing will need it.

### 3.4 Frontends

* `app/leptos-auctioning/index.html` loads `@solana/web3.js` from a CDN
  IIFE. Pin a hash (`integrity=`) or bundle it; a CDN compromise here means
  signed-transaction tampering.
* `marketing/lib/api.ts` types are mostly `?:` optional — the API is stable,
  tighten them (or generate from OpenAPI, see above).
* `marketing/out/` and `tsconfig.tsbuildinfo` are build artefacts on disk
  (gitignored — good) but `.vercelignore` has to exclude them explicitly;
  delete the directory locally so nobody `git add -f`s it.
* The Leptos app has one 1 157-line `lib.rs`. Split by component before it
  grows further.
